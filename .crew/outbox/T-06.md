# T-06 outbox — Core B: eightfold.js, grains.js, sim.js, index.js

## What I did
Created `src/core/eightfold.js`, `src/core/grains.js`, `src/core/sim.js`, `src/core/index.js`
and `tests/eightfold.test.js`, `tests/grains.test.js`, `tests/sim.test.js` — 30 tests total
(12 + 10 + 8), named per PLAN.md §7 / BOARD.md T-06.

- `orbit(points, syms)` — N points × 2n syms → N×2n points, grouped by input point (outer loop
  over points, inner loop over syms), so output order is exactly stable and testable.
- `createBuffer(capacity=20000)` / `emit(buffer, segment, seed, opts)` — `emit` does, in order:
  arc-length resample (fixed spacing, leftover carried on the buffer across calls via
  `buffer._lastPoint`/`buffer._carry`) → seeded jitter per sample, before the group → `orbit()`
  with the buffer's symmetry set (default D4) → write into the preallocated typed arrays at the
  ring cursor, wrapping at `capacity` → recompute `buffer.print` over the valid `origin` prefix.
  The RNG (`buffer._rng`) is created once from `seed` on the buffer's first `emit` call and only
  ever advanced, never re-seeded — this is what makes the same path byte-identical regardless of
  how the caller chunks it into successive `emit` calls.
- `sim.js` exports `positionAt(originX, originY, originZ, birth, phase, t)`: closed-form in `t`
  only (no state, no previous-call dependence) — spawn height before birth, an eased quadratic
  fall, one parabolic damped bounce, then an exact settle at `originY`. Also exports
  `SPAWN_HEIGHT`, `FALL_TIME`, `BOUNCE_TIME`, `BOUNCE_DAMPING`. `phase` is accepted but unused in
  this baseline curve — reserved for T-16's per-grain damping variance (below the freeze line).
- `index.js` re-exports the full public surface (12 names): `dihedral`, `D4`, `mulberry32`,
  `fnv1a32`, `orbit`, `createBuffer`, `emit`, `positionAt`, and the four sim constants.

## Decisions made
1. **`t` (animation time) is always a caller-supplied argument, never read from a clock inside
   the core.** `emit`'s `opts.t` sets `birth` for every grain written in that call, and
   `positionAt`'s `t` param is the only notion of "now" `sim.js` has. This is what keeps the
   "no `performance.`/`Date.now`" boundary rule satisfiable while still having time-based
   animation — the app layer (T-09) owns the clock and passes `t` in.
2. **Reflection matrices in `dihedral.js`'s `orbit`-consuming code rely on exact -1/0/1 entries**,
   so jittered points survive `orbit()` with zero precision loss — this is why
   `test_orbit_is_invariant_under_every_group_element` and the grains-level congruence test can
   both use exact float equality instead of a tolerance.
3. **Golden vectors for `test_sim_matches_shader_reference_vectors` were generated by running the
   actual `positionAt()` once** (via a scratch script) and freezing the output — including one
   entry that lands on `7.460698725481049e-16` rather than a clean `0`, from float subtraction at
   a `t`/`birth` boundary landing a hair inside the bounce window instead of exactly on it. Left
   as-is deliberately: it is a real, reproducible edge case (t=2.6, birth=2, FALL_TIME=0.6) and
   freezing the exact value is a stronger regression fence than rounding it away would be.
4. **`test_grain_count_grows_linearly_with_stroke_length` uses stroke lengths of 10 and 20 world
   units, not 0.5/1.0.** The first attempt at 0.5 and 1.0 units hit floating-point rounding right
   at the arc-length sample boundary (`0.5/0.02` not landing cleanly), so the two strokes lost a
   different number of samples to rounding and the exact-doubling assertion flaked (392 vs 384).
   At 10/20 units the same rounding noise is negligible relative to ~500/1000 samples and the
   doubling comes out exact (4000 vs 8000) — verified by running the real implementation before
   locking in the test, not assumed.
5. **`GrainBuffer` carries a few internal-only fields** (`_rng`, `_lastPoint`, `_carry`) beyond
   the six PLAN.md names (`origin`, `birth`, `phase`, `count`, `cursor`, `print`), plus a public
   `capacity` field. These are implementation state for the ring buffer and the resampler, not
   part of the documented public contract — `render/` should only ever read `origin`, `birth`,
   `phase`, `count`, `cursor`, `print`, `capacity`.

## What T-07 / T-08 need to know
- `npm test` script is `node --test tests/**/*.test.js` (see outbox/T-05.md decision #2 for why
  it isn't the literal `node --test tests/` from PLAN.md/BOARD.md). T-07's `test:boundary` script
  should point at the single file directly (`node --test tests/boundary.test.js`), which does
  work as a bare file path — only bare directory args are the problem on this Node (v24.14.1).
- T-08's `grain.vert.js` must reproduce the 12 golden `(grain, t) → position` triples in
  `tests/sim.test.js`'s `test_sim_matches_shader_reference_vectors` exactly, including the
  `7.460698725481049e-16` case — that's the fence PLAN.md §2 names for the deliberate
  sim.js/shader duplication.
- `emit`'s `opts` shape for the frontend: `{ spacing = 0.02, jitter = 0.006, syms = D4, t }`.
  `t` is required in practice (defaults to 0) — the app must pass its own clock value every call.
- Ring-wrap writes can straddle the array boundary (e.g. one `emit` call's 8 arms landing at
  indices 19998,19999,0,1,2,3,4,5). `pushRange` in T-08 will need to push two ranges to the GPU
  buffer when a single `emit` call's writes wrap — the buffer itself doesn't expose the split,
  only before/after `cursor` and `count`, so T-09's wiring code has to detect the wrap itself.
