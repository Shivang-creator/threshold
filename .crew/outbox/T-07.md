## Decisions made
1. **`test:boundary` targets the file directly (`tests/boundary.test.js`), not a directory.**
   Per the T-05/T-06 outbox notes, `node --test <directory>/` fails on the installed Node
   (v24.14.1) — it tries to `require()` the directory as a CJS module. A single file path doesn't
   hit that problem, so `test:boundary` works exactly as written in PLAN.md/BOARD.md; only the
   plural `test` script needed the glob workaround already applied at T-05.
2. **README.md is new, not edited** — T-01/T-02 didn't create one. I scoped it to what T-07 asks
   for (boundary section, mocked-vs-real table, test list, known duplication) plus a minimal
   pitch/header so the file reads coherently on its own; I did not write deploy instructions,
   screenshots, or anything belonging to later tasks (T-19-T-25), to leave that room for
   pc-deployer/pc-scribe without fighting over the file later.
3. **Ran the sabotage check live, then reverted**, per T-07's acceptance #3: added
   `import * as THREE from 'three';` to the top of `src/core/sim.js`, confirmed
   `npm run test:boundary` exits non-zero (`test_core_imports_no_three_no_react_no_dom` fails with
   a message naming the offending file), then restored `sim.js` and re-ran both `npm run
   test:boundary` (2/2) and `npm test` (52/52) to confirm the revert was clean — diffed against a
   backup copy to be certain no residue was left in the file.
