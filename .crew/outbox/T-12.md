plus the full design-token/layout system in `src/styles.css` and the `@fontsource/instrument-serif`

- Controls: MOTION + SWEEP always visible; a third REPLAY button is CSS-gated to ≤1023px only
  (`.btn--replay-row`), since desktop's replay control is the colophon-embedded one instead.

## Deviation: keyboard tab order
DESIGN §9.2 specifies focus order `MOTION → REPLAY → SWEEP → canvas`. Because the desktop REPLAY
affordance lives inside `Colophon` (bottom-left, matching DESIGN §5.1's exact ASCII placement
"beside the print") while MOTION/SWEEP live inside `Controls` (bottom-right), and tab order follows
DOM source order, actual desktop tab order is **REPLAY → MOTION → SWEEP** (Colophon renders before
Controls in `App.jsx`'s JSX). I chose visual fidelity to §5.1 over exact §9.2 ordering rather than
fragile CSS-grid tricks to decouple visual position from DOM position. All three remain reachable
and operable via keyboard either way — this is an ordering deviation, not an accessibility gap.
Flagging as a needs-decision if pixel/order-exact fidelity to both sections turns out to matter.

## Gap in DESIGN.md, filled with a default (not blocking, flagged)
DESIGN §5.1/§5.2 only specify two breakpoints (desktop ≥1024px, portrait ≤768px) despite T-04's own
acceptance criterion asking for "the rule for what happens in between." I filled the 769–1023px gap
by extending the mobile/portrait layout downward to apply at anything <1024px (single breakpoint at
1024px), rather than leaving that range unstyled. This is my own default, not a DESIGN.md value —
flagging for pc-designer/Crew Chief in case a real tablet-specific treatment is wanted later.
