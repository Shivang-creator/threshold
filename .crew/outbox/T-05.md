# T-05 outbox — Core A: dihedral.js, rng.js, hash.js

## What I did
Created `src/core/dihedral.js`, `src/core/rng.js`, `src/core/hash.js` and their tests
(`tests/dihedral.test.js`, `tests/rng.test.js`, `tests/hash.test.js`) — 20 tests total, all
named per PLAN.md §7 / BOARD.md T-05.

- `dihedral(n)` builds the 2n elements of Dn as exact-integer matrices for n a multiple of 4
  (cos/sin of multiples of 90° rounded to integers). Rotation names: `e r90 r180 r270`.
  Reflection matrices are computed as `rotation_k * mx` (mx = the x-axis mirror) — this is a
  closed-form derivation, not a lookup table — and named from the resulting matrix values
  (`mx md my dm` for D4) so naming is robust regardless of build order. `D4 = dihedral(4)` is
  exported.
- `mulberry32(seed)` — standard mulberry32, each call returns an independent closure with its
  own state cell (verified two generators from the same seed never share state).
- `fnv1a32(f32)` — FNV-1a 32-bit over a `Uint8Array` view of the `Float32Array`'s bytes, so any
  single changed float always changes the print. Empty array returns the raw offset basis
  `811c9dc5`, not a crash.

## Decisions made
1. **Golden vectors were computed from the implementation, not invented.** I ran the actual
   `mulberry32(1)` and `fnv1a32([1,2,3,4])` once via a scratch node script and pasted the real
   output into the tests as the golden vectors. This is standard practice for a deterministic
   PRNG/hash test — the point is regression-proofing against future drift, not predicting the
   algorithm by hand.
2. **`npm test` script changed from `node --test tests/` to `node --test tests/**/*.test.js`.**
   The literal script in PLAN.md §2 / BOARD.md T-07 (`node --test tests/`) does not work on the
   installed Node (v24.14.1): passing a bare directory as a positional arg makes the test runner
   try to `require()` it as a CJS module (`Cannot find module '.../tests'`) rather than
   recursively discovering test files in it. `node --test` with **no** path argument does
   auto-discover `tests/` correctly (Node's own convention-based discovery), and an explicit glob
   (`tests/**/*.test.js`) also works reliably and keeps the script self-documenting about which
   directory is under test. Functionally identical outcome (`npm test` runs every file under
   `tests/`); only the invocation string differs from the one written in the planning docs.
   T-07 will carry this forward to `test:boundary` if the same issue applies there.
3. Fixed a real assertion bug caught by the D4 test itself: applying a rotation matrix to the
   origin can legitimately produce `-0` (e.g. `-1 * 0`), and Node's `assert.equal` (strict/
   SameValue) treats `-0 !== 0`. Fixed by comparing `Math.abs(...)` rather than loosening the
   guarantee.
