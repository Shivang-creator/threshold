# T-02 · Hello-journey stub — done

## What shipped
A deliberately minimal walking skeleton for the render side, per PLAN.md's file layout:

- `src/main.jsx` — mounts `<App/>` into `#root`, imports `src/styles.css`.
- `src/app/App.jsx` — composition root; renders `<Scene/>`. Nothing else yet (site frame is T-12,
  WebGL-capability detection is T-13).
- `src/render/Scene.jsx` — `<Canvas>` (dpr [1,2], antialias) + a `CameraFraming` component that
  sets a fixed camera position `[0, 4.5, 6]` looking at the origin. This is intentionally NOT
  `render/Rig.jsx` from PLAN.md's tree — Rig.jsx bundles the key light, ambient fill and idle
  drift, which is T-11's job and out of scope here.
- `src/render/Ground.jsx` — a 12x12 plane at y=0, unlit `meshBasicMaterial` (`#141414`) so it's
  visible with zero light rig. The wet-stone material lands at T-11.
- `src/render/useDrag.js` — a small hook: `useDrag(onPoint)` returns pointer handlers that read
  `event.point` (R3F already raycasts mesh pointer events, so no manual `THREE.Raycaster` was
  needed for this stub) and call `onPoint({x, z})` on down/move, tracking drag state with a ref
  and pointer capture. `Ground.jsx` wires this to `console.log("[drag] ground point", point)`.
  This hook's shape is designed to be the thing T-08/T-09 extend — swap the console.log for a
  write into `core/grains.js` — without touching the handler wiring.
- `src/styles.css` — html/body/#root sized to viewport, dark background, `touch-action: none` on
  canvas so drag doesn't fight the browser's scroll/zoom gesture on touch.

Not built, deliberately (per task scope — these are T-08/T-09/T-11/T-12): the grain renderer, the
shaders, the Eightfold/core wiring, the light rig, bloom, the wet-stone material, the site frame.

**`npm run build`** — succeeds. `dist/` produced, 32 modules transformed, no errors (only a
routine "chunk >500kB" advisory, expected pre-code-splitting).

**`npm run dev`** — started on port 5183 and driven with a real, headed-capable Chrome (Playwright
MCP's browser wasn't available in this sandbox — no Google Chrome.app and no sudo to install it —
so I downloaded Playwright's own Chrome-for-Testing bundle via `npx playwright install chromium`,
which needs no sudo, and drove it directly with the `playwright` package's `chromium.launch({
executablePath })`). Confirmed:
- A `<canvas>` mounts and fills the viewport (1280x800 in the test).

  background, correctly perspective-framed by the fixed camera — see
  `/private/tmp/.../scratchpad/t02-loaded.png` (local to this session; not a repo artifact).
- Simulating a mouse-down + 5x mouse-move + mouse-up over the canvas produced 16 console lines of
  `[drag] ground point {x: ..., z: ...}` with continuously varying, sane x/z values — confirms the
  raycast-onto-ground-plane path works end to end.
- Zero page errors. One harmless `favicon.ico` 404 (browser auto-request, not app-caused).

**`npm test`** — 20/20 passing (pc-backend's T-05 core landed in parallel; confirms no conflict
between the render stub and the core work).
